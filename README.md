# Monolith

**Monolith** — личное приложение одного человека, который льёт белый арбитраж трафика. Оно ставится на iPhone как сайт на домашний экран (PWA в Safari), без AltStore и без аккаунта Apple Developer. Сервер на Windows отдаёт и страницы, и API. На главном экране внутри приложения заголовок по-прежнему «Дисциплина» — так на макете. Под иконкой на домашнем экране написано Monolith. Иконка — куб на воде. Экран запуска — туманный берег с надписью MONOLITH.

Пример в базе — день **14 ноября 2026**, капитал **$1 000**. Цифры на экранах те же, что на макетах: баланс $789.40, прибыль за день +$34.20, пять связок, четыре живых гео и одно в стопе.

Семь экранов: главный, финансы, связки, гео, задачи, журнал решений, правила. Тёмная тема, карточки «jelly» с зазором 14pt, шрифт Manrope. Цвета разделов: бирюза — финансы, янтарь — связки, тёмно-синий — гео, фиолетовый — задачи, коралл — журнал, зелёный — правила. В меню «•••» есть монохром.

## Что внутри

- `web/` — PWA на Vite и обычном TypeScript. Сборка кладётся в `web/dist`, сервер отдаёт её с `/`.
- `server/` — API на Python (FastAPI, SQLite). OpenAPI: `/docs`. Пути данных остаются `/api/v1/...`.
- `ios/` — прежнее приложение SwiftUI. Оно больше не ставится на телефон и оставлено как архив вёрстки. Рабочий клиент — PWA.
- `start-monolith.bat` — запуск на Windows одним двойным щелчком.

На телефоне ключ вводится один раз и лежит в памяти устройства. Снимок и очередь правок сохраняются локально. Без сети правки копятся и уходят на `POST /api/v1/sync`, когда связь возвращается. Service worker держит оболочку приложения и ту же очередь.

## Запуск на Windows одним щелчком

Нужен Python 3.11 или новее. Node на машине с сервером не нужен, если вы взяли архив из GitHub Actions: в нём уже лежит собранный `web/dist`.

1. Скачайте установщик с [python.org](https://www.python.org/downloads/windows/) и на первом экране включите **Add python.exe to PATH**.
2. Распакуйте архив `monolith-windows` (или клонируйте репозиторий и один раз соберите сайт, см. ниже).
3. Дважды щёлкните `start-monolith.bat`.

Скрипт создаёт `server\.venv`, ставит зависимости, при первом запуске пишет `server\.env` с двумя случайными ключами и печатает ключ телефона в это окно. Затем открывает сайт на [http://127.0.0.1:8741/](http://127.0.0.1:8741/). Окно не закрывайте. Остановка — Ctrl+C.

Проверка API с этого же компьютера:

```powershell
curl http://127.0.0.1:8741/health
```

Ответ: `{"ok":true,"name":"Дисциплина"}`.

Если репозиторий клонирован без `web/dist`, на машине с Node 22:

```powershell
cd web
npm ci
npm run build
```

После этого тот же `start-monolith.bat`.

## Служба Windows

Порт **8741** слушает только localhost. Наружу его открывает Tailscale, не проброс на роутере.

### Планировщик заданий

Откройте PowerShell **от имени администратора** в папке `server`:

```powershell
cd server
powershell -ExecutionPolicy Bypass -File .\install\install-service.ps1
```

Скрипт делает то же окружение и `.env`, заполняет базу примером и регистрирует задание **DisciplinaServer**. Оно стартует вместе с Windows от SYSTEM и поднимает процесс заново, если тот упал.

Остановить службу, не удаляя базу:

```powershell
powershell -ExecutionPolicy Bypass -File .\install\uninstall-service.ps1
```

Посмотреть лог в консоли, без службы:

```powershell
powershell -ExecutionPolicy Bypass -File .\install\start-console.ps1
```

Повторить пример с нуля (сотрёт ваши проводки):

```powershell
.\.venv\Scripts\python.exe -m app.seed
```

### NSSM, если он уже стоит

Из папки `server`, после того как `.venv` и `.env` созданы:

```powershell
nssm install Monolith "$PWD\.venv\Scripts\python.exe" "-m" "app"
nssm set Monolith AppDirectory "$PWD"
nssm start Monolith
```

`nssm remove Monolith confirm` снимает службу. База в `server\data` при этом не удаляется.

### Docker

Из папки `server`, когда `.env` уже создан:

```powershell
copy .env.example .env
docker compose up -d --build
```

Контейнер публикует API на `127.0.0.1:8741`. В этот образ PWA не входит: для телефона используйте `start-monolith.bat` или службу Windows из корня репозитория, где рядом лежит `web\dist`.

## Tailscale и экран «Домой» на iPhone

Сервер не должен торчать в интернет. Телефон попадает к нему через вашу tailnet, по HTTPS.

1. Поставьте [Tailscale](https://tailscale.com/download/windows) на Windows и на iPhone. Войдите в один аккаунт.
2. В админке Tailscale включите MagicDNS.
3. На сервере, когда Monolith уже слушает `127.0.0.1:8741`:

```powershell
tailscale serve --bg --https=443 http://127.0.0.1:8741
tailscale serve status
```

4. Имя машины будет вида `https://имя-компьютера.ваша-tailnet.ts.net`.
5. На iPhone откройте этот адрес в **Safari** (не в Chrome). Ключ ещё не нужен, чтобы страница открылась: его спросят на первом экране.
6. Нажмите «Поделиться» → **На экран «Домой»**. Имя — Monolith, иконка — куб. Запуск идёт отдельным окном без панели Safari, со сплэшем туманного берега.
7. Вставьте ключ телефона из `server\.env` (`DISCIPLINA_IOS_API_KEY`). Он сохранится на телефоне. Повторно его не спрашивают, пока вы не смените его в меню «•••».

Не открывайте порт 8741 в брандмауэре для сети «Public» и не делайте проброс на роутере. Ключ в заголовке `X-API-Key` остаётся вторым замком, если кто-то окажется в той же tailnet.

`tailscale serve` нужен именно для HTTPS: Safari ставит PWA и service worker на защищённом адресе. Голый `http://100.x.y.z:8741` для «На экран Домой» не используйте.

## Ключи и что кому можно

Заголовок каждого запроса, кроме `/health` и самой страницы: `X-API-Key`.

| Ключ | Читать | Дневная статистика, проводки, ставки гео | Журнал | Правила, задачи, связки |
| --- | --- | --- | --- | --- |
| Телефон | да | да | да | да |
| Бот | да | да | да | нет |

Полезные пути:

- `GET /api/v1/snapshot` — весь экранный снимок одним ответом.
- `GET /api/v1/rules/check` — сверка цифр с правилами. В ответе отдельные списки `violations`, `warnings` и `signals`.
- `POST /api/v1/journal` — сводка бота.
- `POST /api/v1/bundles/{id}/stats` — расход, доход, клики и конверсии за день. Итоги связки пересчитываются из дней.
- `POST /api/v1/sync` — пачка правок, которые телефон накопил без сети.

На примере нарушений нет: Мексика уже в стопе, дневной расход $38 из $50 — это предупреждение, а Польша даёт сигнал масштабирования (ROI выше 50% дольше семи дней).

Уведомления в PWA — локальные, через разрешение Safari. Service worker уже принимает Web Push (`push`), но сервер ключ VAPID не рассылает: это заготовка, не отдельная capability.

## Сборка и тесты

Сайт, из папки `web`:

```powershell
npm ci
npm run build
```

Тесты сервера, из папки `server`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

На Linux и macOS то же самое с `bin/python` вместо `Scripts\python.exe`.

GitHub Actions (файл `.github/workflows/web.yml`) на каждый push в `main` собирает сайт, гоняет pytest и кладёт архив **monolith-windows**: сервер, собранный `web/dist`, `start-monolith.bat` и этот README.

## Архив iOS

`ios/Monolith.xcodeproj` — старый клиент SwiftUI, iOS 17+, только iPhone. Его цвета, радиусы и блик карточек в `ios/Monolith/Design/Theme.swift` остаются источником вёрстки PWA. Workflow `.github/workflows/ios-ipa.yml` по-прежнему может собрать неподписанный IPA, но на телефон это приложение больше не ставим: бесплатный Apple ID, AltStore и продление подписи каждые 7 дней больше не нужны.

## Что проверено

Проверено здесь: `pytest` (снимок примера, права двух ключей, синхронизация, страница `/` не перекрывает `/api/v1`, `/health` и `/docs`), сборка `npm run build`. Живой процесс отдал PWA и снимок; семь экранов сняты в Chrome на логическом iPhone 440×956 (картинка 1320×2868).

Не проверялось на самом Windows и iPhone: двойной щелчок по bat, служба планировщика, NSSM, `tailscale serve` и жест «На экран Домой».
