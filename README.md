# Дисциплина

Личный учёт одного человека, который льёт белый арбитраж трафика. Семь экранов на iPhone и сервер с данными. Веб-интерфейса нет: телефон и бот ходят в API разными ключами.

Пример в базе — день **14 ноября 2026**, капитал **$1 000**. Цифры на экранах те же, что на макетах: баланс $789.40, прибыль за день +$34.20, пять связок, четыре живых гео и одно в стопе.

## Что внутри

- `ios/` — приложение SwiftUI, iOS 17+, только iPhone. Русский интерфейс, шрифт Manrope, карточки «jelly», переключаемая монохромная тема.
- `server/` — API на Python (FastAPI, SQLite). OpenAPI: `/docs`.

На телефоне есть замок (код и Face ID или Touch ID), локальный кэш и очередь правок, которая уходит на сервер, когда сеть возвращается, и локальные уведомления по срабатыванию правил.

## Сервер на Windows

Нужен Python 3.11 или новее и PowerShell. Порт API — **8741**. Слушать его нужно только на localhost, наружу его открывает Tailscale, не проброс на роутере.

### 1. Поставить Python

Скачайте установщик с [python.org](https://www.python.org/downloads/windows/) и на первом экране включите **Add python.exe to PATH**. В новом окне PowerShell:

```powershell
python --version
```

Должно быть 3.11 или выше.

### 2. Поставить зависимости и ключи

Откройте PowerShell **от имени администратора**, перейдите в папку `server` этого репозитория и выполните:

```powershell
cd server
powershell -ExecutionPolicy Bypass -File .\install\install-service.ps1
```

Скрипт делает следующее:

1. Создаёт виртуальное окружение `.venv`.
2. Ставит зависимости из `requirements.txt`.
3. Если файла `.env` ещё нет, записывает два случайных ключа: `DISCIPLINA_IOS_API_KEY` для телефона и `DISCIPLINA_BOT_API_KEY` для бота.
4. Заполняет базу примером (`python -m app.seed`).
5. Регистрирует задание планировщика **DisciplinaServer**. Оно стартует вместе с Windows от SYSTEM и поднимает процесс заново, если тот упал.

Ключи лежат в `server/.env`. Файл не коммитьте. Ключ телефона потом вставляется в меню «•••» на айфоне. Ключ бота — в того ассистента, который читает статистику и пишет сводки.

Проверка с этого же компьютера:

```powershell
curl http://127.0.0.1:8741/health
```

Ответ: `{"ok":true,"name":"Дисциплина"}`. Описание API: [http://127.0.0.1:8741/docs](http://127.0.0.1:8741/docs).

Остановить службу:

```powershell
powershell -ExecutionPolicy Bypass -File .\install\uninstall-service.ps1
```

База при этом не удаляется. Посмотреть лог в консоли, без службы:

```powershell
powershell -ExecutionPolicy Bypass -File .\install\start-console.ps1
```

Повторить пример с нуля (сотрёт ваши проводки):

```powershell
.\.venv\Scripts\python.exe -m app.seed
```

### 3. Docker, если он удобнее службы

Из папки `server`, после того как `.env` уже создан:

```powershell
copy .env.example .env
docker compose up -d --build
```

Контейнер публикует порт только на `127.0.0.1:8741`. В `.env` всё равно задайте свои ключи, не оставляйте `dev-ios-key` и `dev-bot-key`.

### 4. Tailscale

Сервер не должен торчать в интернет. Телефон и бот попадают к нему через вашу tailnet.

1. Поставьте [Tailscale](https://tailscale.com/download/windows) на Windows-сервер и на iPhone. Войдите в один аккаунт.
2. В админке Tailscale включите MagicDNS.
3. На сервере API уже слушает `127.0.0.1:8741`. Включите HTTPS-прокси Tailscale:

```powershell
tailscale serve --bg --https=443 http://127.0.0.1:8741
tailscale serve status
```

4. Имя машины будет вида `https://имя-компьютера.ваша-tailnet.ts.net`. Его и вставляйте в телефон как адрес сервера.
5. Не открывайте порт 8741 в брандмауэре для сети «Public» и не делайте проброс на роутере. Ключ в заголовке `X-API-Key` остаётся вторым замком на случай, если кто-то окажется в той же tailnet.

Если `tailscale serve` не хотите, можно ходить по HTTP на адрес `100.x.y.z:8741`. Для этого в `.env` поставьте `DISCIPLINA_HOST` равным этому адресу и перезапустите задание. В приложении тогда адрес `http://100.x.y.z:8741`. Для личного приложения, которое не идёт в App Store, HTTP внутри tailnet разрешён (ATS ослаблен в Info.plist). HTTPS через `tailscale serve` всё равно лучше.

## Ключи и что кому можно

Заголовок каждого запроса, кроме `/health`: `X-API-Key`.

| Ключ | Читать | Дневная статистика, проводки, ставки гео | Журнал | Правила, задачи, связки |
| --- | --- | --- | --- | --- |
| Телефон | да | да | да | да |
| Бот | да | да | да | нет |

Полезные пути:

- `GET /api/v1/snapshot` — весь экранный снимок одним ответом.
- `GET /api/v1/rules/check` — сверка цифр с правилами. В ответе отдельные списки `violations`, `warnings` и `signals`.
- `POST /api/v1/journal` — сводка бота.
- `POST /api/v1/bundles/{id}/stats` — расход, доход, клики и конверсии за день. Итоги связки пересчитываются из дней.
- `POST /api/v1/sync` — пачка правок, которые телефон накопил без сети.

На примере нарушений нет: Мексика уже в стопе, дневной расход $38 из $50 — это предупреждение, а Польша даёт сигнал масштабирования (ROI выше 50% дольше семи дней).

## Приложение на один iPhone

Нужны Mac с Xcode 16 или новее, iPhone и платный аккаунт Apple Developer. TestFlight и ad hoc без него не ставятся. В App Store приложение не публикуется.

### 1. Подпись

1. Откройте `ios/Disciplina.xcodeproj`.
2. Цель **Disciplina** → **Signing & Capabilities**.
3. Включите **Automatically manage signing**, выберите свою Team.
4. Bundle ID по умолчанию `app.disciplina.ios`. Если он занят, замените на свой, например `app.вашеимя.disciplina`.

### 2. Сборка на подключённый iPhone

1. На iPhone: Настройки → Конфиденциальность и безопасность → режим разработчика, включить.
2. Подключите телефон кабелем, нажмите «Доверять».
3. В Xcode выберите этот iPhone и нажмите Run.

Первый запуск просит код из 4 цифр и предлагает Face ID (на старом телефоне — Touch ID). После этого открывается главный экран. Пока адрес сервера пустой, видны данные примера, правки пишутся на телефон. В «•••» вставьте адрес Tailscale и ключ из `.env`, нажмите «Сохранить сервер».

### 3. TestFlight

1. В App Store Connect создайте приложение с тем же Bundle ID. Имя можно «Дисциплина».
2. В Xcode: Product → Archive.
3. Organizer → Distribute App → App Store Connect → Upload.
4. В TestFlight добавьте себя внутренним тестировщиком и установите сборку с телефона.
5. Экспортное шифрование: в Info.plist уже стоит `ITSAppUsesNonExemptEncryption = false`, отдельную анкету обычно спрашивать не будут.

### 4. Ad hoc, если TestFlight не нужен

1. Возьмите UDID: Xcode → Window → Devices and Simulators, либо на телефоне подключитесь и скопируйте Identifier.
2. В developer.apple.com зарегистрируйте устройство и сделайте Ad Hoc provisioning profile для этого Bundle ID.
3. Archive → Distribute App → Ad Hoc, поставьте профиль, экспортируйте `.ipa`.
4. Поставьте его через Finder/Apple Configurator или Devices в Xcode.

Монохром включается в том же меню «•••». «Проверить уведомление» через пару секунд показывает локальный баннер — это заглушка, не push с сервера. Настоящие баннеры приложение ставит само, когда `/rules/check` возвращает новое нарушение или предупреждение и тумблер уведомлений включён.

## Проверки

Тесты сервера, из папки `server`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

На Linux и macOS то же самое с `bin/python` вместо `Scripts\python.exe`.

## Что проверено, а что нет

Проверено здесь: `pytest` (снимок примера совпадает с текстами макетов, права двух ключей, синхронизация, нарушение стоп-лосса связки), живой процесс API и OpenAPI на `/docs`.

Не проверено: сборка Xcode и скриншоты симулятора — на этой машине нет macOS и Xcode, поэтому снимков SwiftUI нет. Не ставилась служба Windows, не поднимался Tailscale, Face ID на устройстве не нажимался. Цвета, радиусы, тени и блик карточек в `ios/Disciplina/Design/Theme.swift` совпадают с `jelly.css`, `common.css` и HTML экранов.
